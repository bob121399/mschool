# Как запустить MSchool и увидеть его вживую

Два пути. Оба запускают **настоящее приложение**: работают вход, роли, формы, база, приглашения и переходы.
Данные в обоих случаях вымышленные (2 демо-компании).

| | Локально (ноутбук) | В облаке (Vercel + Supabase) |
|---|---|---|
| Время | 15–20 мин в первый раз, дальше 2 мин | ≈ 20 мин один раз |
| Стоимость | $0 | Supabase $0; Vercel Hobby $0 (Pro $20/мес для коммерческого показа) |
| Ссылка для других | Нет, только на вашем компьютере | Да, `https://…vercel.app` |
| Фоновые задачи (worker) | Работают | Не размещаются (новые PDF и отчёты стоят в очереди) |
| Живой ИИ | Если добавить ключ OpenAI | Если добавить ключ OpenAI |

## Путь 1. Локально — самый надёжный, проверен в этой среде

1. Установите **Docker Desktop** (запустите его), **Node.js 22 LTS** и **Git**.
   На Windows: установите WSL2 (`wsl --install`) и выполняйте команды в терминале Ubuntu.
2. В терминале:
   ```bash
   git clone -b mvp-iteration-02 https://github.com/bob121399/mschool.git
   cd mschool
   npm run demo
   ```
3. Дождитесь строки «Сервер запущен» и откройте **http://localhost:3000**. Логины и пароль скрипт печатает
   в терминале и сохраняет в `.secrets/demo-access.txt`.
4. Вход суперадмина: после пароля попросит код. Получите его в другом окне терминала: `npm run demo:code`.
5. Письма-приглашения смотрите в локальном почтовом ящике: http://localhost:54324.

Повторный запуск: `npm run demo -- --skip-build` (≈ 2 мин). Остановка: `Ctrl+C`, затем `npx supabase stop`.
Подробный сценарий показа: `docs/demo-guide.md`.

## Путь 2. В облаке — ссылка, которую можно открыть с любого устройства

Нужен компьютер с Node.js 22 и Git (Docker не нужен), а также два бесплатных аккаунта.

1. **Supabase** (https://supabase.com): зарегистрируйтесь и создайте организацию.
   Затем Account → **Access Tokens** → Generate new token. Проект создавать не нужно, скрипт создаст `mschool-demo`
   во Франкфурте.
2. **Vercel** (https://vercel.com): зарегистрируйтесь. Затем Account Settings → **Tokens** → Create.
3. На своём компьютере:
   ```bash
   git clone -b mvp-iteration-02 https://github.com/bob121399/mschool.git
   cd mschool
   npm ci
   export SUPABASE_ACCESS_TOKEN=…        # токен из шага 1
   export SUPABASE_DB_PASSWORD=…         # придумайте надёжный пароль базы (≥ 16 символов)
   export VERCEL_TOKEN=…                 # токен из шага 2
   # по желанию, для живого ИИ:
   # export OPENAI_API_KEY=… OPENAI_TUTOR_MODEL=… OPENAI_ASSESSOR_MODEL=… OPENAI_WORKER_MODEL=…
   npm run demo:hosted
   ```
4. Скрипт создаст проект Supabase, применит миграции, заполнит демо-данные, опубликует сайт на Vercel и напечатает
   адрес и доступы. Они же сохраняются в `.secrets/hosted-demo-access.txt`. Код для суперадмина: добавьте
   напечатанный TOTP-секрет в Google Authenticator.

Что важно знать:
- `npm run demo:hosted` ещё ни разу не запускался против настоящих Supabase и Vercel: в этой среде нет ваших аккаунтов.
  Если упадёт, пришлите вывод терминала — исправлю. Повторный запуск безопасен: проект и данные не дублируются.
- Регистрация новых компаний по ссылке закрыта, чтобы посторонние ничего не создавали. Входите демо-аккаунтами.
- Встроенная почта Supabase не отправляет письма на вымышленные адреса — приглашения в облачном демо не доставляются.
- Альтернатива без запуска на своём компьютере: добавьте те же три значения в настройки облачного окружения Claude
  (меню окружения → Edit), откройте новую сессию и попросите «разверни демо по docs/deploy.md».

## А Railway?

Можно, но сейчас не рекомендую. Railway запускал бы web и worker из `Dockerfile`, а сборку Docker-образов в этой среде
проверить не удалось: реестр образов отвечал ошибкой лимита. Базу всё равно брать в Supabase. Если Railway нужен
(например, чтобы worker тоже работал в облаке), первым шагом нужно проверить сборку: `bash scripts/dev/docker-build-check.sh`
на машине с Docker.
