# Демо MSchool: как запустить и показать

Демо работает **локально на вашем ноутбуке** и использует **синтетические данные**: две вымышленные компании
(A и B), 24 сотрудника, курсы и треки для каждого грейда, счета и метрики. Реальных клиентов в нём нет, наружу
ничего не отправляется: письма-приглашения попадают в локальный почтовый ящик Mailpit.

## 1. Один раз: подготовка ноутбука (≈ 20 минут)

| Что | Где взять |
|---|---|
| Docker Desktop (запущен, ≥ 4 ГБ RAM для Docker) | docker.com → Docker Desktop |
| Node.js 22 LTS | nodejs.org |
| Git | git-scm.com |
| Windows: WSL2 + Ubuntu, все команды выполнять в терминале Ubuntu | `wsl --install` |

```bash
git clone -b mvp-iteration-02 https://github.com/bob121399/mschool.git
cd mschool
npm run demo
```

Первый запуск скачивает образы Supabase и собирает приложение (5–15 минут в зависимости от интернета).
В конце в терминале появится **карточка доступа**: адрес, логины, пароль. Она же сохраняется в
`.secrets/demo-access.txt`. Откройте http://localhost:3000.

## 2. В день показа

```bash
npm run demo                  # чистый запуск: данные и пароли создаются заново (≈ 2 минуты)
npm run demo -- --skip-build  # быстрее, если код не менялся
npm run demo -- --keep-data   # продолжить с теми данными, что остались после прошлого показа
npm run demo:code             # код MFA для входа суперадмина (в другом окне терминала)
```

Остановка: `Ctrl+C`. Supabase продолжит работать в Docker; полностью выключить его можно командой `npx supabase stop`.

Совет: запустите демо за 10 минут до встречи и откройте четыре вкладки (в режиме инкогнито, чтобы роли не
смешивались): сотрудник, HR компании A, HR компании B и суперадмин.

## 3. ИИ на демо: два варианта

**Без ключа (по умолчанию).** Все экраны, данные, история проверок, метрики и биллинг работают. Живые вызовы ИИ
(тьютор, проверка ответа, генерация курса, отчёты агентов) честно отвечают «ИИ-провайдер не настроен», без
подставных ответов. Это осознанное правило продукта: никаких скрытых заглушек.

**С живым ИИ (рекомендуется для инвесторов).** Добавьте в `.env.local` (файл создаётся при первом запуске):

```bash
OPENAI_API_KEY=sk-...
OPENAI_TUTOR_MODEL=<модель>
OPENAI_ASSESSOR_MODEL=<модель>
OPENAI_WORKER_MODEL=<модель>
OPENAI_EMBEDDING_MODEL=text-embedding-3-small
```

Затем выполните `npm run probe`. Он проверит, что выбранные модели поддерживают нужный формат ответа и эмбеддинги,
и должен завершиться без `BLOCKED`. После этого перезапустите демо: `npm run demo -- --skip-build`. Стоимость
одного показа — центы (несколько десятков вызовов). Сделайте один прогон заранее: живой ИИ на этом проекте ещё не
проверялся (блокер BLK-01).

## 4. Сценарий показа (≈ 12 минут)

**0. Проблема и продукт (1 мин).** Обучение сотрудников по внутренним документам компании: HR загружает
регламенты, получает курсы и треки по грейдам; сотрудник учится с ИИ-тьютором, который отвечает только по
источникам компании; итоговые задания проверяются по рубрике, итоговый балл считает база данных, а не модель.

**1. Сотрудник** — `emp.a.junior1@…`
- Главная: текущий трек, прогресс, следующий урок.
- «Весь маршрут»: путь от Junior дальше по грейдам, уроки открываются по порядку.
- Урок: текст, **источники** (из каких документов компании собран урок), самопроверка, итоговое задание.
  С живым ИИ задайте тьютору вопрос по уроку, затем вопрос «не по теме»: тьютор откажется выдумывать.
- «История»: попытки с разбором по критериям и возможностью апелляции.

**2. HR компании A** — `hr.a@…`
- Обзор: чек-лист запуска и состояние команды.
- Сотрудники: приглашение (письмо видно в Mailpit http://localhost:54324), CSV-импорт, массовое назначение трека.
- Источники знаний: подтверждённый PDF и скан без текста. Скан помечен на ручную проверку, система не делает вид,
  что прочитала его.
- Курсы: опубликованный курс неизменяем, правки — только через новую версию (черновик v2). Публикует только
  человек.
- Апелляции: HR может вручную пересмотреть решение, действие попадает в журнал.
- Оплата: активные места и счета.

**3. Изоляция компаний** — `hr.b@…` во второй вкладке. Это другая компания со своими данными; данных компании
A она не видит ни в интерфейсе, ни через API. Изоляция обеспечивается на уровне базы и покрыта
автоматическими тестами.

**4. Суперадмин** — `superadmin@…` + код из `npm run demo:code`
- Без второго фактора (MFA) глобальный доступ закрыт: это проверяет и приложение, и база.
- Метрики: MRR/ARR, NRR/GRR, места; демо-компании включаются переключателем, по умолчанию не смешиваются с
  реальными.
- Компании: просмотр данных клиента только с указанием основания, просмотр логируется.
- Агенты: очередь фоновых задач (отчёты HR-аналитика, поддержка, sales) со статусами и повторами.

**5. Зрелость (1 мин) — говорить честно.** Готово: три роли, изоляция данных, неизменяемые версии курсов,
детерминированная оценка, биллинг и метрики; 25 unit-, 56 интеграционных и 30 end-to-end тестов проходят.
До пилота нужно: проверить живой ИИ на выбранных моделях, подключить антивирус для загрузок и OCR,
развернуть staging/production с доменом и почтой.

## 5. Если что-то пошло не так

| Симптом | Что сделать |
|---|---|
| «Docker не запущен» | Откройте Docker Desktop, дождитесь статуса Running |
| «Порт 3000 занят» | Закройте другой сервер (найти его: `lsof -i :3000`) |
| Не принимается пароль | После каждого `npm run demo` без `--keep-data` пароль новый — смотрите `.secrets/demo-access.txt` |
| Код MFA не подходит | Код живёт 30 секунд — запросите новый `npm run demo:code`; проверьте, что время на ноутбуке синхронизировано |
| Ошибки Supabase после сна ноутбука | `npx supabase stop && npm run demo` |
| «ИИ-провайдер не настроен» | Ожидаемо без ключа (см. раздел 3) |
| В отчётах нет текстовых выводов, обращения в поддержку уходят человеку | Ожидаемо без ключа: отчёты строятся по метрикам, а текст ИИ не генерируется (см. раздел 3) |
